# API切换器

一个强大的 API 管理和切换工具，支持多种 AI API 提供商，并具有智能错误自动恢复功能。

## ✨ 主要功能

### 1. API 管理
- 支持多个第三方 API 提供商（DeepSeek、Kimi、GLM、Z.AI、自定义 OpenAI-compatible / Anthropic-compatible）
- 快速切换不同的 API 配置
- 支持 Claude Code / Codex CLI 官方账号快照切换
- 支持切换前预览和配置健康检查
- 安全的密钥管理
- 配置导入/导出
- 在 Profile 编辑器中测试连接、刷新模型列表、查看 provider 专属提示

### 2. 自动续跑功能
- 自动检测任务是否完成
- 智能续跑未完成的任务
- 支持 Claude Code 和 Codex CLI
- 可配置的续跑策略

### 3. Git 版本管理 ⭐
- **自动创建 Git 快照**（默认开启）
  - 对话开始时自动创建快照
  - 错误恢复前自动创建快照
  - 自动续跑时自动创建快照

- **本地版本管理**
  - 自动检测并初始化本地 Git 仓库
  - 已有仓库会直接复用，不覆盖 remote、分支或用户身份配置
  - 使用本地提交记录保存代码状态，不依赖远端仓库
  - 已有全局实名 Git 身份时继续沿用；缺少身份时才写入本地兜底身份
  - 支持查看提交历史
  - 回滚前自动保留安全标签，方便找回回滚前版本

### 4. 错误自动恢复 ⭐
- **智能识别 10 种 API 错误类型**
  - 内容超长
  - 速率限制
  - 认证错误
  - 权限错误
  - 配额超限
  - 模型过载
  - 超时错误
  - 网络错误
  - 流式连接中断（包括 Codex compact 任务断流）
  - 服务器错误
  - 无效请求

- **5 种自动恢复策略**
  - 压缩并继续（内容超长）
  - 等待后重试（速率限制）
  - 指数退避重试（服务器、网络或流式连接问题）
  - 友好提示（认证/权限/配额）
  - 中止执行（无效请求）

- **详细的错误统计**
  - 可视化统计卡片
  - 按错误类型分析
  - 错误时间线
  - 导出详细报告

### 5. SSH 与浏览器 Profile
- 把本机第三方 API 或官方账号快照推送到 SSH 服务器
- 从 SSH 服务器拉取第三方 Claude/Codex API 配置
- 在 SSH 服务器上检查、安装/修复、暂停和卸载 Claude/Codex 远端自动续跑
- SSH 代理支持按服务器独立保存目标分流，为不同服务分别选择订阅和固定节点；部署及订阅热更新沿用各服务器的绑定
- 支持把 `HF_TOKEN`、Google Drive/Gemini、代理等环境变量永久写入或删除于本机 Windows 用户、所选 SSH 登录用户
- 管理 Chrome / Edge 托管 Profile，用于本机隔离 ChatGPT / Claude 登录态
- 支持托管浏览器 Profile 的加密迁移、站点数据清理和整目录重置

### 6. Win11 AI 代理
- 支持从订阅链接拉取 Clash/mihomo 节点；服务端拒绝常见客户端标识时会自动切换兼容标识重试
- 支持保存多个订阅并按服务手动选线：OpenAI/Codex、Claude Code、Google AI、YouTube 等内置站点及每条自定义域名/IP 可分别绑定订阅与节点；不同服务使用独立健康检查，固定节点不会自动换出口
- Win11 / SSH 的订阅选择旁提供“标记家宽 / 非家宽”入口，支持“未标记 / 家宽 / 非家宽”手动分类，订阅列表同步显示标记；标记不代表出口 IP 已经实测验证
- 打开“管理目标分流”会按标记自动补齐当前位置的未配置目标草稿：仅 OpenAI/Codex、Claude、Gemini 优先家宽；所有内置普通网站（含 X/Twitter、Reddit、YouTube、Google 搜索/账号、GitHub、Hugging Face、Discord、Telegram）优先非家宽。保存并应用后生效；无对应可用订阅或有多个候选时不猜选，可展开修改清单查看原因
- 已有绑定、固定节点、明确关闭的目标和手动“跟随默认线路”不会被覆盖；手动默认选择跨窗口重开保留。每个目标可在订阅下拉中选择“按用途重新分配”，非家宽自动节点策略仍只在同订阅内进行故障切换
- 自动检测疑似旧版 X / Twitter、Reddit 家宽默认绑定，“整理旧版分流”一次生成当前位置的非家宽调整草稿。旧版没有来源记录，不能断定是自动还是手动选择，因此不静默迁移、不直接改运行线路；固定节点、自选候选、关闭目标和本次手动修改保留
- “目标分流”总览按目标显示订阅、节点策略和失效提示；未启用站点可折叠。点击“管理目标分流”集中启用站点、添加域名和改线路，统一保存并应用；Windows 与 SSH 使用相同编辑流程，草稿不会提前改动正在运行的代理
- 节点选择支持地区/名称多关键词搜索，显式区分“订阅内自动切换”和“固定节点”；保存前可展开修改清单，SSH 复制需明确勾选接收服务器
- 节点策略新增“自选候选自动切换”：同一订阅中勾选 1–16 个候选，可上移/下移调整优先顺序，搜索不会丢失勾选；采用 [mihomo fallback](https://wiki.metacubex.one/en/config/proxy-groups/fallback/) 按可用性及顺序选择，服务组保持各自健康检查，不扩展到未选节点。单候选无备用，固定节点仍不会自动换出口；连通检查不能保证账号权限、模型权限或每次 API 调用一定成功
- 分流编辑器支持“批量设置”：批量指定订阅、固定节点或自选候选池，也可按用途重新分配、跟随默认、启用/停用网站与自定义目标。仅修改当前位置勾选目标草稿，设置线路不改变启用状态；跨 SSH 服务器仍需明确选择复制接收方
- 定时刷新读取当前分组和分流绑定涉及的已保存订阅，不刷新未使用的收藏订阅、不提交表单草稿；忙碌、启动失败或下载异常会续排重试，页面切走后仍执行，程序启动时恢复已开启任务。SSH 定时目标在开启时保存，页面临时勾选变化不改变定时目标；旧版没有保存目标的设置需重新勾选服务器并开启一次。真正退出程序后订阅定时任务暂停，保留运行的 mihomo 仍可执行已配置的节点故障切换
- “运行状态 / 网址去向”只读检查受管内核的实际规则、策略组选择和已有探针时间；可输入网址比较已保存与运行线路，不发送目标请求。Windows 与所选 SSH 服务器共用检查窗口，报告可脱敏复制
- 服务绑定和订阅后台刷新不会切换当前订阅页面、主节点或 Codex/Claude 登录状态；绑定缓存缺失、订阅被删除或路由应用失败时会保留原运行配置并明确提示
- 链接临时失效时保留最后一次成功缓存，不会因为拉取失败清空当前可用节点
- 支持导入本地 Clash/mihomo YAML，源文件移动或删除后仍可从托管缓存恢复
- mihomo 内核会在代理可用后仅后台刷新官方版本元数据，不与 Codex 首次连接争抢带宽；“更新内核”按钮才下载发行包，并校验大小、SHA-256 digest、平台架构和实际版本，运行中只暂存且不会自动断网重启
- 运行时会把当前节点和最多 4 个合格备用节点交给 mihomo `fallback` 组，以 OpenAI API 真实无认证响应做端到端健康检查；首次失败即触发复检，新连接自动转到首个可用备用节点
- Win11 启动验证并行检测 OpenAI API、ChatGPT、Claude 和 Gemini，并仅给内核故障切换一次有上限的初始化复检；逐节点长会话深测留在手动体检与后台订阅更新，不再卡住日常启动
- 默认兼容分流也会为代理节点使用大陆可达的加密 DNS 引导，AI/自定义代理域名的 DNS 则显式通过 `AI-PROXY`；同时开启多 IP 并发拨号和 TCP keepalive，减少 IPv4/IPv6 路径不均与长会话 NAT 超时
- 启动时只补齐本工具明确拥有且缺失的代理环境变量，不覆盖用户另行设置的非空值；若确认是本工具留下的死代理，会自动恢复启动前的 Windows、VS Code 和系统代理设置
- “清理脏代理”会显式检查失效回环环境变量、WinINET 当前用户系统代理和 VS Code 残留；来源不明的项目先列出无凭据清单，确认时重新核对原端点和监听状态，正常代理不会被清理
- 可选“共享到 WSL”会识别默认发行版的真实网络模式：WSL1/镜像模式保持 Windows 回环监听，WSL2 NAT/VirtioProxy 使用动态宿主网关，并只对白名单中的当前 WSL 私有子网开放 mihomo
- WSL 共享会写入可撤销的 shell、fish 与 VS Code Remote 环境入口，同时无凭据并行验证 Codex/OpenAI 和 Claude Code 官方路径；不会读取或改写 API Key、OAuth Token 或登录文件
- “优化 WSL 网络”会保留其他设置并合并微软推荐的镜像网络、DNS 隧道和自动代理，原 `.wslconfig` 使用不覆盖旧备份的方式保存；停止代理时同步清理受管 WSL 入口和精确防火墙规则
- Windows 本机 mihomo 运行日志改为有界诊断：启动前按大小上限轮转历史文件，正常运行不再持续记录目标域名，健康状态由本机控制器提供
- 全新 SSH 服务器会先只安装受管 mihomo 内核，再执行隔离节点验证；内核下载失败时保留已有可用版本，不会破坏正在工作的代理配置
- 默认 AI 主线路的自动选优、自动刷新和热更新排除香港节点；香港节点可手动选择，明确绑定的网站订阅池不受这一 AI 筛选限制
- “测速全部节点”覆盖当前订阅全部节点、不受勾选和筛选影响；原“测速勾选/筛选”保留范围操作。Win11 的 TCP 节点连续检测 3 次，UDP/其他传输全部使用隔离临时内核实测 HTTPS 转发（最多 4 路并发），香港节点也会测试
- 基础测速先显示、先缓存，随后才对有限候选通过隔离临时代理三轮验证 OpenAI API、ChatGPT 出口、Claude 和 Gemini；短探针通过后，对最多 5 个候选执行两轮 1 MiB 下载、512 KiB 上传完整性检查及无 token 的官方 compact 路径预检，验证期间不会切换系统代理或当前运行节点。列表的“未测质量”是另一个出口质量项目，不表示延迟未测
- SSH 的全量测速仍是所选服务器到节点的 TCP 端口检测，不代表 UDP 协议或 AI 服务实际可用；结果缺失会明确提示失败，不能把未返回的数据当成未操作过
- 默认 AI 主线路的后台订阅热更新和自动备用节点必须先通过上述隔离深测，失败会保留当前运行节点；明确绑定的网站订阅池使用内核 HTTPS 健康检查，不要求 AI 深测。深测约使用 3.2 MiB/候选，是 Codex 长会话网络风险筛查，不代表真实账号 compact 一定成功
- 新增可选“严格隐私（应用层）”：凡是已经进入 mihomo 的公网流量都会 fail-closed 走节点，代理内部域名解析使用 DoH 并关闭 IPv6；严格模式下订阅拉取不会绕过失效代理直连
- 该功能仍不是 VPN/TUN，无法强制接管忽略系统代理的程序、系统 DNS 或任意 UDP；切换后需重启 Codex、Claude Code、VS Code 和终端。托管 Chrome/Edge 在严格模式生效时会显式绑定本机代理、禁用 QUIC，并限制 WebRTC 非代理 UDP
- 本地 Clash/mihomo YAML 只导入 `proxies` 节点，不继承原文件的 `dns`、`tun`、`fake-ip` 等顶层隐私设置

## 🚀 快速开始

### 下载和安装

1. 下载 `API切换器.exe`
2. 双击运行即可，无需安装其他依赖

> 默认使用 `python build_exe.py` 打包为单文件 `dist/API切换器.exe`；只有调试依赖收集问题时才需要 `python build_exe.py --onedir` 生成文件夹版。
>
> 正式发布使用 CPython 3.12，并先执行 `python -m pip install -r requirements-release.txt`；该清单锁定了已验证的完整构建依赖。随后运行 `python release_check.py --build`，会依次执行静态检查、全量测试、单文件构建和隔离启动冒烟验证。

### 首次使用

#### 设置不同目标的代理线路

1. 先在订阅区保存并拉取所需订阅（例如家宽 A、机房 B），也可导入本地 YAML。
2. Win11 代理页点击服务下方的线路卡片；SSH 页先勾选服务器，再点击“编辑已选服务器的目标分流”。
3. 点击“订阅标记”将 A 标为家宽、B 标为非家宽，再点“按标记分流”补齐当前位置草稿，默认分配见下表。同类有多个可用订阅时不猜选，可在各目标下手动选择；已有绑定、明确关闭的目标与本次手动修改保留。同一订阅内也可为各服务固定不同节点。
4. “订阅首选 + 故障切换”仅使用所选订阅的节点池；选择具体节点后不会自动换出口。网站自动池最多 16 个节点，AI 池仍为 5 个；优先近期连通成功的网站备用节点，未知/失效节点仍可由内核复测。订阅更新后固定节点消失，会提示重新选择并保留原运行配置。
5. 第三方 API 的网址可直接添加为自定义目标，再单独选线。更具体的子域名/IP 规则优先于宽泛规则；同一目标以自定义设置为准，包括恢复跟随默认线路。自定义条目未单独绑定时跟随“自定义目标默认线路”。
6. 点击“保存并应用”一次应用修改。SSH 可逐台编辑，也可将当前草稿复制到其他已选服务器；部分服务器失败会保留其草稿，重试时只处理未成功项。未部署的服务器保存后在下次部署生效。

未勾选的内置或自定义目标不新增专属规则，仍遵循该位置的默认代理范围；未单独绑定的自定义目标沿用“自定义目标默认线路”。WSL 共享沿用 Win11 同一套分流规则。

订阅标记仅表达手动分类，不代表出口 IP 实测属性；保存标记不会切换运行线路。“按标记分流”只修改当前编辑位置的草稿，确认修改清单后需点击“保存并应用”。

| 默认订阅类型 | 目标 |
| --- | --- |
| 家宽 | OpenAI / Codex、Claude Code、Google AI / Gemini |
| 非家宽 | X / Twitter、Reddit、YouTube、Google 搜索/账号、GitHub、Hugging Face、Discord、Telegram |

这是按流量成本与出口稳定性取舍的可修改默认策略，并非这些服务必须使用某种 IP。自定义目标不猜测类型，Google AI 的更具体规则优先于 Google 网站规则。明确关闭过的站点不会被自动启用，可先手动启用后再补齐线路。

打开“管理目标分流”会自动检测疑似旧版 X / Twitter、Reddit 家宽绑定，点击“整理旧版分流（N）”即可批量生成非家宽调整草稿，再核对修改清单并“保存并应用”。只整理当前 Win11 / SSH 位置，其他服务器不变；原设置可通过“撤销当前修改”恢复。

旧版未记录分配来源，检测只能识别旧规则的特征，不能保证不是手动选择。因此打开窗口仅检测，不自动清空或切线；固定节点、自选候选池、手动默认、关闭目标和本次编辑过的目标都不会整理。只有唯一可用的已标记非家宽订阅时才生成调整；没有合适订阅或多个候选时保留原选择并说明原因。其他需要调整的目标仍可使用“批量设置 → 按用途重新分配”，或手动指定线路。

自动池通过内核持续健康检查（间隔 10 秒、单次超时 5 秒）选择仍可用的节点；YouTube 使用专用探针，其余普通网站使用通用连通探针，不保证每个具体网站或账号都可用。故障切换不跨订阅，也不兜底直连；只有一个可用缓存节点时会显示“暂无备用”。切换针对后续连接，已断开的页面、下载或会话可能需要重试。

SSH 测速结果只对当前选择的服务器集合及连接参数有效，切换服务器或修改主机、端口、用户名后需重新测速；不会将本机测速缓存或另一台服务器的结果显示为当前服务器延迟。一次分流配置生成中，同一订阅的所有策略组共用同一份缓存快照，避免订阅刷新时混用新旧节点。

#### 确认网址会走哪条线路

Win11 代理页点击“运行状态 / 网址去向”；SSH 页先勾选服务器，再点击“检查已选服务器的分流 / 网址去向”。窗口一次只检查当前选择的位置，不扫描所有服务器。运行总览按代表域名/IP 显示已保存线路、内核策略组和节点选择；输入完整网址后仅保留主机名/IP，路径、查询参数不会发送或持久保存。

检查只读取 mihomo 的 `/configs`、`/rules` 和 `/proxies`，核对实际代理端口，拒绝截断或检查中途变更的响应；不进行测速、DNS 查询、代理清理或节点切换。读取失败可直接刷新重试，不会沿用旧结果。快照 60 秒后提示刷新；探针记录超过 180 秒或时间异常会标为过期。域名遇到 IP、属地、规则集或进程相关的前置规则时，只显示条件候选，不冒充确定出口。节点名称通过部署文件与缓存的连接指纹映射；无法核实名称时保留内核标识，未核对内存参数的映射会明确提示。

这里的“策略组一致”只核对此代表域名/IP 的路由意图，不代表所有子域名、整个 IP 段或节点连接参数都已核实。历史探针通过也不保证账号、长会话或真实出口 IP 可用；该检查不会验证浏览器/WSL 是否已经继承代理。

## 📁 数据存储位置

软件自身数据统一保存在当前 Windows 用户的 Roaming 配置目录：

```text
%APPDATA%\API切换器\
```

这里包含 Profile 列表、备份、日志、使用统计、托管浏览器 Profile，以及 keyring 不可用时的 DPAPI 加密密钥备份。可以通过环境变量 `API_SWITCHER_DATA_DIR` 指定自定义数据目录。首次运行新版时，会把旧的项目内 `storage` 目录内容复制迁移到新位置，已存在的新数据不会被覆盖。

数据目录选择优先级：

1. 环境变量 `API_SWITCHER_DATA_DIR`
2. 程序同目录的 `data_dir.txt`，或用户配置目录里的 `data_dir.txt`（可在“通用设置 > 数据存储”里选择目录生成）
3. 程序同目录的 `portable.flag` 或环境变量 `API_SWITCHER_PORTABLE=1`，使用程序旁边的 `data` 目录
4. Windows Roaming 目录 `%APPDATA%\API切换器`
5. LocalAppData / 临时目录 fallback

“通用设置 > 数据存储”可以打开当前数据目录、复制路径、选择自定义目录、启用便携模式或恢复默认；更改目录会复制当前数据，并在下次启动后生效。

## 🔐 跨电脑迁移 Profile

### 单独迁移 Codex / Claude 官方登录账号

在 **Codex CLI** 或 **Claude Code** 页的“官方账号”区域，点击“导出当前登录”，或在某个已保存账号卡片上点击“导出登录”。设置至少 8 位迁移密码后，会生成独立的 `.asxaccount` 加密登录包，只包含所选客户端的一个官方登录账号，不包含其他账号、第三方 API Key、代理、SSH、浏览器数据或会话记录。

在另一台电脑安装本软件后，进入对应客户端页面，点击“导入登录包”，选择文件并输入同一个密码。导入后可点击“切换到此账号”，通过现有切换预览应用到本机，并重新打开对应客户端/终端会话。**导入本身不切换当前登录**，同名但不同凭据的账号保留为独立条目；本机原有代理和第三方 API Profile 不随登录包迁移。

登录包使用密码加密，导入后凭据重新存入目标电脑的本机密钥存储，不直接复制源电脑的 DPAPI 密文。请仅迁移自己拥有或获授权使用的账号；文件与密码分开保管，不上传仓库或发送到公开聊天。凭据过期、撤销或多设备刷新冲突时仍可能需要重新登录，登录包不是永久通行凭证。

兼容边界：Codex 当前登录导出要求明确使用 `cli_auth_credentials_store = "file"`，不会把 `auto` / `keyring` 下可能残留的 `auth.json` 当作当前登录，也不会替你修改正在使用的凭据存储设置。Claude 登录包面向 Claude Code 的 claude.ai OAuth 账号凭据，不是浏览器或 Claude Desktop 登录迁移。参见 [Codex 官方认证与缓存迁移说明](https://learn.chatgpt.com/docs/auth#fallback-authenticate-locally-and-copy-your-auth-cache)及 [Claude Code 凭据管理说明](https://code.claude.com/docs/en/authentication#credential-management)。

### 完整配置与 API Profile 迁移

在“备份管理”中使用“导出 ZIP”可以生成完整本地配置 ZIP。它面向本机配置备份/迁移，包含已保存的 Claude/Codex API Profile、官方账号快照、SSH 服务器、浏览器 Profile 元数据、活动选择，以及这些条目引用的 API Key、账号 token、SSH 密码和私钥口令。ZIP 内的密钥数据会用迁移密码加密；导入 ZIP 时会先显示包内 Profile/密钥数量，同名 Profile 会被替换，不同名 Profile 会保留。导入过程具有事务回滚保护，失败时会恢复 Profile、相关密钥和环境检测设置；同时创建的普通备份仅保护 Claude/Codex/VS Code 客户端运行配置，不包含可独立恢复的密钥快照。

在“备份管理”中使用“导出迁移包”可以生成加密的 `.asxprofile` 文件。迁移包包含 Claude/Codex/SSH 的第三方 API Profile 元数据、API Key、SSH 密码、SSH 密钥口令，以及浏览器 Profile 目录中的 Cookies、Local State、本地存储、IndexedDB、Session Storage、Service Worker 等登录态相关数据。导入到另一台电脑时，输入同一个迁移密码，软件会把密钥重新写入新电脑的本机凭据存储，并把浏览器数据恢复到本机托管的 `browser_profiles` 目录。

浏览器迁移会跳过 Cache、崩溃日志、SingletonLock 等临时/锁定文件。Chromium 在 Windows 上可能使用系统账号加密 Cookies，完整目录迁移也可能受浏览器自身加密机制限制；如果导入后登录态不可用，需要在新电脑重新登录一次。

浏览器 Profile 使用独立 `user-data-dir` 和 `Default` 分区启动，可隔离 Cookies、本地存储、IndexedDB、缓存、扩展和历史等站点数据。启动时可以固定窗口尺寸和语言代码，减少同一台机器上的环境差异；但网页通常不会读取一个稳定的“设备 ID”，而是综合 IP、系统、浏览器版本、显卡/WebGL、字体、Canvas、Audio、时区、屏幕等信息形成指纹。因此跨电脑迁移可以尽量保留登录态和站点状态，但不能保证网页看到完全相同的设备指纹。

## 📖 使用场景

#### 场景 1: 长时间对话
当使用 Claude Code 进行长时间对话时，如果遇到内容超长错误，系统会自动执行压缩命令并继续，无需手动干预。

#### 场景 2: 频繁调用
当 API 请求过于频繁触发速率限制时，系统会自动等待指定时间后重试，确保任务顺利完成。

#### 场景 3: 服务器不稳定
当遇到服务器繁忙、超时、网络断开或 `remote compact task` 流式连接中断/上游 503 重置时，系统会使用指数退避算法自动重试；如果 compact 任务断流，会重新触发压缩再继续。

#### 场景 4: 代码版本管理
系统会在对话开始和错误恢复前自动创建本地 Git 快照，如果代码出现问题，可以轻松回滚到之前的任意版本。这个功能面向本地 vibe coding 保护，不要求配置 GitHub 或远端仓库；如果项目本身已经配置了远端和实名身份，也会原样保留，不影响你继续手动 push。执行回滚前还会创建安全标签，便于找回回滚前的状态。
